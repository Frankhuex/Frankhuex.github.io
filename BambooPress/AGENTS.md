# BambooPress 开发规范

本文件适用于 `BambooPress/` 及其子目录，并与仓库根目录的 `AGENTS.md` 一起遵守。BambooPress 是静态、多作品的小说阅读站，采用原生 HTML、CSS 和 JavaScript ES modules；目前无需构建步骤或后端。保留用户已有的未提交改动，修改范围应与任务一致。

## 架构与模块职责

- `books.js`：书目注册表，集中维护作品 ID、展示信息、封面及正文加载入口。数组顺序即书架顺序。
- `books/<id>.js`：单本作品的结构化正文，只导出数据，不放置页面逻辑。
- `library.js`：作品查找、旧 ID 兼容、正文加载、进度键生成、HTML 转义与跨书搜索调度。
- `main.js`：公共页面控制器，负责路由、书架、作品详情、搜索结果及页面切换。
- `reader.js`：公共阅读器，负责目录、正文、署名、章节导航、定位、进度保存及事件清理。
- `search.js`：正文和元数据匹配、结果排序、高亮。
- `settings.js`：阅读设置及本地存储封装。
- `index.html`、`search.html`：页面外壳；共用脚本、样式及阅读设置结构。
- `style.css`：公共样式、响应式布局、阅读排版及动画；`images/` 存放封面，`fonts/` 存放字体和许可证，`tests/` 存放验证脚本。

## 数据驱动与页面通用性

1. 新增同类作品应通过新增正文文件、封面和书目配置完成，沿用现有书架、详情页、阅读器和搜索功能。
2. 禁止在公共渲染、搜索、路由或 CSS 中按具体书名、作者名、作品 ID 编写作品专属分支。可选显示内容应通过数据字段表达；扩展能力时定义通用字段及默认行为。
3. 书架、目录、章节导航、署名和搜索结果必须由数据生成，不手写每本作品的页面或章节列表。
4. 封面统一读取 `coverImage`；无图片时使用 `coverColor` 和书名生成占位封面。颜色使用六位十六进制格式，图片路径相对 `BambooPress/`。
5. 书目与正文目前都保存标题和作者，更新时同步核对。书目 `authors` 是展示字符串，正文 `authors` 是作者数组，允许展示格式不同，但作者身份应一致。
6. 阅读设置在站内共用，阅读进度按作品隔离。旧链接和旧进度通过 `previousIds`、`legacyDefault` 等通用配置兼容，保持兼容逻辑集中管理。
7. 插图、脚注、富文本、多卷等能力超出现有文本结构；实现前先扩展统一数据格式，再同步调整渲染、搜索和验证，避免为单本作品复制页面。

## 书目注册格式

`books.js` 导出 `books` 数组，每项字段约定如下：

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `id` | string | 必填，全书库唯一且稳定，与正文 `novel.id` 一致，用于链接和进度存储 |
| `title` | string | 必填，作品标题 |
| `authors` | string | 必填，作者展示文案 |
| `description` | string | 必填，作品简介 |
| `coverColor` | string | 建议提供，六位十六进制占位封面颜色 |
| `coverImage` | string | 可选，例如 `images/vx1.png` |
| `date` | string | 可选，按作品原始日期信息展示 |
| `previousIds` | string[] | 可选，改名后的历史 ID；不得与其他作品当前或历史 ID 冲突 |
| `legacyDefault` | boolean | 旧无书籍参数链接的默认作品，全库最多一项；新增作品不自动设置此项 |
| `load` | function | 必填，按需导入正文模块，返回含 `novel` 导出的模块 |

不要因排序、改标题或更换封面随意修改作品 ID。确需迁移 ID 时保留历史 ID，并验证旧链接和进度迁移。

## 正文文档格式

正文采用 UTF-8 的 JavaScript 数据模块，使用 `export const novel = {...};`。对象内容保持可序列化，只保存文本、数组和普通对象。

| 层级 | 字段 | 约定 |
| --- | --- | --- |
| 作品 | `id`、`title`、`authors`、`chapters` | ID 与书目一致；`authors` 为作者字符串数组；`chapters` 为非空、有序数组 |
| 作品 | `version` | 可选，作品版本信息 |
| 章节 | `id`、`title`、`parts`、`paragraphs` | 章节 ID 在作品内唯一且稳定；可沿用 `c0`、`c1` 等格式 |
| 章节 | `excerpt` | 可选，章节副标题或摘句；缺省或空字符串均表示不展示 |
| 作者片段 | `id`、`author` | `parts` 的每项描述一个写作片段；作者属于作品作者数组；建议 ID 使用 `c0-s0` 等含章节前缀的格式 |
| 自然段 | segment[] | `paragraphs` 的每项是一个非空片段数组，对应一个自然段 |
| 文本片段 | `text`、`part` | `text` 为非空纯文本字符串，`part` 引用本章节 `parts` 中存在的 ID |

- `parts` 按原文写作顺序排列，同一作者再次接续可以拥有新的片段 ID。片段 ID 应在作品内唯一，以便目录锚点准确定位。
- 同一自然段内发生作者交接时，在该自然段数组中放入多个文本片段，保留原文段落边界；每个片段分别记录作者归属。
- 新自然段使用新的数组项；段内确有换行时使用 `\n`。保持原文顺序、标点、署名和空格，不以手工空格模拟排版缩进。缩进、行距、字体等由公共样式控制。
- 文本按纯文本渲染，禁止将 HTML 标签、内联样式或可执行代码作为正文格式。作品信息插入 HTML 字符串时必须转义，正文与高亮使用安全的 DOM 文本接口。
- 章节及片段 ID 会进入阅读链接，段落索引用于进度定位。调整已有章节顺序、ID、段落切分前，应评估并处理旧定位的兼容性。
- 导入文档时核对章节顺序、作者身份、接续边界、番外归属及正文完整性，原文中的“番外”等文字按实际语义归入章节或正文。

## 路由、加载与状态

- 使用 `route()` 和 URL 参数接口生成地址，作品详情及阅读链接携带 `book`；阅读定位使用 `chapter`，可附带 `part`、`paragraph`、`ratio`、`q`。保留 `search.html` 搜索入口。
- 正文通过书目 `load()` 按需加载，书架展示无需加载所有正文；跨书搜索遍历书目，单本加载失败时仍返回其他作品的搜索结果。
- 进度键统一通过 `progressKey(bookId)` 生成，读写使用 `settings.js` 的存储封装，避免跨书覆盖。
- 异步页面切换保留过期渲染保护；阅读器注册的事件、观察器和计时器应在离开页面时清理。
- `index.html` 与 `search.html` 的公共外壳目前分别维护。修改页头、阅读设置、公共资源引用时同步检查两页；后续抽取外壳应保持静态站点直接运行能力。
- 资源引用已有 `?v=` 缓存版本约定。修改需发布的资源时检查对应 HTML 和模块导入引用，必要时同步更新版本，确保同一模块使用一致地址。

## 页面与资源约束

- 保持桌面与移动端阅读布局、键盘操作、可访问名称及减少动画偏好支持。封面提供作品相关替代文本，阅读设置和署名显示对所有作品一致生效。
- 页面样式使用公共类和数据字段，不为某本书固定章节数量、正文长度或作者数量。顺序动画应有合理的后续项表现。
- 新增独立 HTML 页面时，沿用根目录 `index.html` 的 Cloudflare Web Analytics 配置，每页仅加载一次；保留现有页面埋点。
- BambooPress 在网站首页归入“小说”。需要调整主站入口时，遵守根目录规范，同步检查根目录 `index.html`、`NewHome/index.html` 和共用 `NewHome/script.js`。
- 保留字体许可证；添加图片和字体时检查实际文件存在、路径大小写及相对路径解析。

## 新增作品与验证

1. 整理并核对原始文档，生成符合上述格式的 `books/<id>.js`。
2. 将封面放入 `images/`，在 `books.js` 登记作品和加载入口，按任务要求确定书架顺序。
3. 检查书目 ID 唯一、正文 ID 一致、章节和片段 ID 唯一、片段引用有效、作者归属正确，以及所有图片和模块路径有效。
4. 涉及正文导入时，为有实际风险的内容边界增加针对性校验，例如章节缺失、段内交接或番外署名；避免只复述实现的测试。
5. 在仓库根目录运行 `node BambooPress/tests/library.test.mjs` 和 `node BambooPress/tests/vx1.test.mjs`；后续新增的相关验证脚本也应运行。提交前运行 `git diff --check`。
6. 修改页面行为或排版时，通过本地 HTTP 服务检查书架、详情、阅读、上下章、目录定位、搜索跳转及刷新后继续阅读；涉及布局时检查桌面和移动端。浏览器验证与数据脚本验证分别如实报告。

## 维护本文档

架构、字段格式、入口、存储规则或验证命令发生变化时同步更新本文件。开发说明应明确区分当前行为和新增约束，不将尚未实现的校验或功能描述为已有能力；当前 `loadBook()` 仅检查作品 ID 和非空章节，完整结构要求由数据整理及验证脚本落实。
