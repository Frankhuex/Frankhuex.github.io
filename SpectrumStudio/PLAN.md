# SpectrumStudio 实现计划

## 1. 项目目标

开发一个纯前端音频频谱可视化视频生成器。用户在浏览器中导入音频、选择频谱样式、添加背景图并调整画面，实时预览后导出带原音频的视频。所有媒体处理默认在用户设备完成，支持作为静态网站部署到 GitHub Pages。

本文为设计与实施计划，当前阶段不编写应用代码。首版优先保证完整歌曲的预览、音画同步与视频导出可靠，再扩展视觉效果。

## 2. 首版功能范围

| 模块 | 首版内容 |
| --- | --- |
| 音频 | 本地导入、时长显示、播放/暂停、进度拖动、音量调节；通过实际解码结果判断文件是否可用 |
| 频谱样式 | 柱状、上下镜像柱状、环形三种预设 |
| 频谱参数 | 颜色或渐变、频带数量、尺寸、位置、灵敏度、平滑程度、频率范围 |
| 背景 | 纯色或本地图片；填充/完整显示；缩放与位置；高斯模糊、亮度、暗色遮罩 |
| 画幅 | 16:9、9:16、1:1；预览保持最终画幅比例 |
| 导出 | 720p/1080p 预设、30 FPS、带音频的视频、进度、取消、下载 |
| 状态反馈 | 导入中、解码中、就绪、分析中、导出中、完成及可操作的错误提示 |

首版导出整首音频；预览音量只控制监听，导出保留原音频电平。暂缓音频裁剪、多音轨、字幕、时间线关键帧、视频背景、粒子系统、4K 与 60 FPS。首版数据仅保存在当前会话，后续再加入项目保存与恢复。

## 3. 技术路线

使用 HTML、CSS、JavaScript ES Modules 构建界面，Canvas 2D 绘制最终画面，Web Audio API 解码和播放音频，Web Worker 执行离线频谱分析。正式导出使用 WebCodecs 编码音视频，并使用经过验证的封装库生成 MP4 或 WebM。依赖采用固定版本，浏览器端直接加载本地构建产物，生产运行无需 Node.js 服务。

具体封装库在技术验证阶段选择：检查维护状态、许可证、流式输出、时间戳处理以及音视频编码接入能力，再固定版本。允许使用开发构建工具；部署产物保持纯静态。

### 3.1 导出能力分级

1. 优先检测 MP4 对应的视频与音频编码配置，以及封装库支持；完整链路可用时提供 MP4。
2. 检测 WebM 对应的编码与封装配置，提供可用的 WebM 导出选项。
3. WebCodecs 路线不可用时，检测 Canvas 捕获与 MediaRecorder 的音视频录制能力，提供实时录制兼容模式，并说明需要播放完整时长、保持页面前台。
4. 如果所有导出路线均不可用，保留编辑和预览，明确显示可采取的操作，例如换用已验证的桌面浏览器。

能力判断覆盖候选分辨率和编码参数，不能仅凭 API 名称存在就启用导出。界面只展示当前设备通过检查的配置；编码初始化或运行失败时保留编辑状态并允许重试。

### 3.2 预览与导出的统一模型

将画面绘制实现为由“项目参数、目标尺寸、时间点、频谱数据”驱动的渲染器。预览和导出调用同一套布局、频率映射、平滑与绘制逻辑，所有坐标和尺寸尽量使用相对画幅的值。

离线分析先生成按固定时间间隔采样的频谱缓存，预览根据音频播放时间读取缓存，导出按帧时间读取相同缓存。音频导入后允许先显示分析进度，待缓存就绪再开放完整频谱预览。这样可以统一拖动、重复播放与导出的画面结果。

## 4. 音频与频谱设计

- 将解码后的 PCM 数据送入 Worker，分块计算 FFT；根据音频时长与采样率估算内存和分析工作量。
- 首版频谱分析合并左右声道能量，避免直接相加波形导致反相抵消；导出音频保留声道，编码要求转换时明确处理策略。
- 使用对数频率分组，让低频、中频、高频在视觉上分布合理；提供可调频率范围与增益，并设置噪声门和幅度上限。
- 将频谱平滑定义在固定分析时间步上，缓存处理结果。拖动进度直接定位缓存，不依赖此前是否播放。
- 分析缓存按时间与频带保存压缩后的幅度数据，不长期保存每帧完整 FFT 结果。预览与导出按时间插值读取。
- 声音播放使用音频时钟；界面动画根据该时钟取时间。播放、暂停、跳转及播放结束均更新明确的状态。

FFT 窗口大小、分析步长、缓存精度和频带数量在原型阶段通过听感、画面与性能对比确定，随后作为默认值固定。

## 5. 画面与交互设计

桌面采用中央预览、侧边参数区、底部播放控制与导出入口；小屏采用预览在上、参数分组在下。参数区按“音频、频谱、背景、画幅、导出”组织，提供可直接使用的默认效果。

背景图支持 cover 和 contain，明确显示裁切结果。图片模糊先在扩边的离屏画布中处理，再裁切到输出尺寸，避免边缘出现透明黑边。背景处理只在图片、尺寸或相关参数变化时重新执行，频谱动画直接复用背景缓存。高斯模糊先验证 Canvas 滤镜的目标浏览器表现；需要回退时，对缩小的背景进行可分离高斯处理并缓存。

预览内部渲染尺寸可以随设备性能降低，布局始终按最终画幅计算。导出读取独立的目标尺寸。画幅切换保留相对位置与尺寸，背景按当前适配方式重新计算。

导出期间固定一份项目参数快照，显示当前阶段、已完成帧数与总体进度；预计剩余时间在获得足够样本后展示。首版导出时锁定会影响项目内容的编辑操作，并保留取消按钮。

## 6. 视频导出流程

1. 检查音频、目标尺寸、帧率、编码器配置及输出方式，估算内存占用并建立导出任务。
2. 固定项目快照，准备背景缓存和频谱缓存。
3. 按帧编号计算时间：第 n 帧对应 n / FPS 秒；用整数时间戳表达，帧数根据音频时长确定，末帧时长正确截断。
4. 逐帧绘制 Canvas，创建 VideoFrame 并交给 VideoEncoder；设置有界队列，按编码器背压控制生产速度，及时释放帧对象。
5. 从原音频 PCM 分块生成 AudioData，通过 AudioEncoder 编码；音视频时间戳共用零点，处理末尾音频块与编码延迟。
6. 封装编码数据，完成编码器 flush 和文件收尾，再提供下载。
7. 无论完成、失败或取消，都关闭编码器、释放缓冲与临时资源；取消任务不生成可误认为完整结果的文件。

优先使用封装库支持的流式文件写入；浏览器具备相应文件能力时让用户选择保存位置。其他环境使用有界内存缓冲生成 Blob，并按预估体积设置限制。频谱缓存、已解码 PCM 与输出数据共同计入内存预算。大文件能力通过测试后再开放，首版不承诺无限时长。

兼容录制模式复用相同渲染器，按实际音频时钟绘制，合并画布视频轨道与音频输出轨道。开始录制前完成准备，录制结束后等待数据收尾，取消时停止所有轨道。

## 7. 建议代码结构

| 路径 | 职责 |
| --- | --- |
| index.html | 页面骨架与语义化控件 |
| styles.css | 布局、主题与响应式样式 |
| js/app.js | 初始化、界面事件与状态协调 |
| js/project.js | 参数结构、默认值、合法范围及项目快照 |
| js/audio.js | 音频读取、解码、播放和时间控制 |
| js/analysis-worker.js | FFT、频带映射和平滑缓存生成 |
| js/renderer.js | 统一画面绘制、背景缓存与画幅布局 |
| js/styles/ | 柱状、镜像、环形样式实现 |
| js/export/ | 能力检测、WebCodecs 导出、封装及兼容录制 |
| vendor/ | 固定版本的第三方运行依赖及许可证 |

按职责拆分即可，实施时可根据实际规模合并小模块，避免过早搭建插件框架。

## 8. 开发阶段与交付标准

| 阶段 | 工作内容 | 完成标准 |
| --- | --- | --- |
| P0：导出技术验证 | 使用短音频和简单动画验证 WebCodecs、封装、下载及录制回退；选择依赖 | 至少一条离线导出链路成功，生成含声音的文件；记录已验证环境与可用格式 |
| P1：基础编辑器 | 音频导入播放、Worker 分析、柱状频谱、背景图、画幅与基础调节 | 完整歌曲可以播放、暂停和跳转；参数变化即时反馈；切换画幅布局正确 |
| P2：视觉样式 | 镜像与环形、渐变、频率范围、平滑、背景缓存与小屏布局 | 三种样式共用参数模型；相同时间点的画面可重复；背景调节不持续拖慢动画 |
| P3：完整导出 | 接入统一渲染器、音频编码、队列控制、进度、取消和错误恢复 | 完整歌曲成功导出，声音和画面同步，取消后可再次导出，失败后保留项目 |
| P4：稳定性与发布准备 | 跨浏览器检查、完整歌曲与长音频测试、资源释放、静态部署验证 | 达到下方验收标准，页面说明已验证能力及限制；部署产物无需后端运行 |

先完成 P0，再决定正式导出链路细节。开发完成后在本地验证和整理结果，发布与提交按后续任务要求执行。

## 9. 验收与测试

- **音频正确性：** 使用单音、扫频、静音和左右声道测试素材检查频带响应；静音时稳定收敛，反相立体声仍有合理频谱。
- **同步：** 使用固定时间点的脉冲声及对应画面验证输出，在起始、中段、末尾检查；目标偏差控制在一帧量级，记录播放器与测量方式。
- **导出文件：** 核对容器、编码、尺寸、帧率、音轨、可播放性与时长；音视频终点差控制在一帧或一个编码音频包的量级，具体按编码格式评估。
- **画面一致性：** 在固定时间点比较预览与导出画面，检查频谱形态、颜色、布局、背景裁切和模糊边缘。
- **场景覆盖：** 至少覆盖约 10 秒、5 分钟、30 分钟音频；30 分钟测试用于确定和公布首版实际支持范围。测试三种画幅及 720p/1080p。
- **资源与恢复：** 重复导入、更换图片、重复导出、取消、损坏文件和编码失败后，界面可恢复，内存不随重复操作持续明显增长。
- **浏览器：** 优先验证开发设备上的桌面 Chrome/Edge，再验证 Safari、Firefox 的可用路径。移动端单独记录预览和导出能力，不直接沿用桌面结论。
- **部署：** 通过 HTTP 本地服务及目标静态路径加载，检查模块路径、Worker 路径、依赖许可证和控制台错误。

测试结果记录浏览器版本、系统、硬件、媒体长度、导出参数、耗时和峰值内存，避免将单台设备的表现推广到所有环境。

## 10. 风险与后续扩展

| 风险 | 处理策略 |
| --- | --- |
| 编码能力因浏览器和系统变化 | 运行时检测并试初始化，提供可用格式和录制回退 |
| 长音频 PCM 或输出文件占用过多内存 | 导入前后估算、分析缓存压缩、有界编码队列、优先流式输出，依据测试设置限制 |
| 高分辨率下模糊和绘制成本较高 | 缓存静态背景、降低预览分辨率、导出使用背压控制 |
| 页面进入后台导致录制节奏变化 | 录制模式提示保持前台并检测页面状态；离线导出按明确时间戳生成帧 |
| 封装或时间戳错误导致偏移、截尾 | P0 尽早验证真实文件，加入脉冲同步与末尾测试 |

后续可扩展项目配置保存、音频裁剪、歌曲信息文字、封面、更多样式、关键帧、4K/60 FPS，以及本地 Node.js + FFmpeg 导出器。扩展时继续复用项目参数和统一渲染器。
